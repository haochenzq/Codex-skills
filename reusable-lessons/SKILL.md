# 提取与整理可复用经验

明确要求提取、整理或沉淀可复用经验时，先提炼，再按第 2 节决定是否归档。只要求总结、审阅或预览时，在回复中交付。去重、协作同步和接续点按各节条件处理。

## 1. 范围与取证

- 默认处理当前项目和本轮工作。用户指定项目、对话、文件或时段时，以指定范围为准。
- 有候选经验后，再定位对应的现行规则、记忆或专项资料，确认是否已有记录及应写入何处。
- 本轮复盘以本轮证据为主。用户要求回顾历史，或需要验证问题是否反复出现、经验是否适用于其他任务时，按范围查阅相关历史正文，按线程 ID 去重，必要时检索归档。证据不足时说明缺口。
- 对照用户明确决定、现行文件、实际产物及实测记录。区分已验证事实、推测、临时例外和被替代方案，分别记录准备完成、执行成功及用户验收。证据不足时保留不确定性。

## 2. 提炼与归档

只提取会改变以后判断或执行的经验。写明适用条件、可观察的问题、做法和验证方式，必要时引用证据。多项同时变化时记录组合效果，单项归因须有证据。省去一次性细节和重复过程。

| 内容 | 归属 |
| --- | --- |
| 有明确依据的长期项目约束、权限和验收要求 | 项目规则 |
| 判断方法、教训和有适用条件的实测结果 | 项目记忆或已有专项资料 |
| Agent 的分工、交接、共享资源和责任边界 | 现有协作规则 |
| 跨项目规则或稳定个人偏好 | 按现有分层和明确授权维护相应全局资料 |

没有可复用经验，或现有记录已完整覆盖时，简报结论即可。有需要补充的经验时，优先更新对应的权威记录。没有合适入口时，在回复中给出可直接使用的条目。仅在用户要求落盘或项目明确要求归档时，按项目惯例建立最小记录。经验可独立归档，无需升级为规则。

## 3. 精简、去重与处理冲突

- 已有明确授权的改动直接按授权执行。尚未获授权且涉及删除有效内容、覆盖原始记录或实质改变现行规则的改动，先预览涉及的文件和条款、拟改文字及理由，经用户明确同意后写入。
- 确认只约束涉及的改动。先完成并回读其余可独立执行的修改，按第 5 节记录待续事项。收到确认后从待办处继续，完成写入和回读，并按需更新接续点。
- 去重和冲突处理限于与本次经验直接相关的条款。用户明确要求扩大范围时，按指定范围处理。修改前读取最新文本，保护用户手改、他人改动和有效引用。合并同义条款，修订已确认过时的现行要求，保留有效历史和证据。
- 保持原意和执行效果，核对执行人、触发条件、范围、前置条件、权限、例外、顺序、交付与验收。要求逐字保留的内容原样保留。
- 按上级有效要求、适用范围及同一事项的最新明确决定处理实质冲突。默认项与例外、不同角色或模式的合理差异，写清各自条件。无法裁决时保留有效约束，报告冲突出处、影响和待决定事项。
- 同一约束优先维护一处。若合作方只能看到自己的副本且必须执行该约束，保留最短等义条款，注明来源并核对一致性。

## 4. 多 Agent 协作

经验直接涉及实际协作职责或交接时，才检查并按需维护协作文件。只收录对方可见、可执行的职责及必要交接内容。本地规则、内部操作、私有资料和专属记忆留在各自一侧。

- 按需写清输入、定稿、修改、交付、验收、例外批准及共享文件写入各归谁负责。交接注明现行入口、版本、必要材料、状态、限制和验收点。
- 缺项写明补齐条件。来源冲突写明具体冲突、适用范围和各项的权威来源。

只有明确适用于本轮的授权才可向合作方同步或修改远端副本。沿用现有渠道和入口，只同步必要的协作规则与交接事实。分别报告发送、保存和回读状态。历史对话仅供取证。

## 5. 更新接续点与回读

整理结果影响后续动作，或项目明确要求时，按需更新现有接续点。记录有变化的状态、采用版本、待办及下一步，保留有效事项和引用。没有接续点时，仅在确有待续事项或项目明确要求的情况下按项目惯例新建。

回读实际改动，核对约束、状态、版本和引用，并修正受影响入口的旧口径。简报列出提炼出的经验、写入位置或未写入的原因，以及需要后续处理的事项。

遇到待确认或实际阻碍，先完成可独立执行的工作，再说明已完成的内容、待处理事项和恢复条件。

### 判定示例

- 误用旧稿导致返工时，提炼定稿前核对现行主稿、版本和差异的方法。逐字保留按项目已确认规则执行。
- 旧规则和现行规则指定不同提交人时，先核是否适用不同入口或模式。用户已明确统一分工时，更新相关现行入口。
- 记录时长实测时，写明模式、计量口径及结果。单次成功或拦截只证明对应组合的观测结果，正式上限须有充分依据。
