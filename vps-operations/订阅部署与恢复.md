# 订阅部署与恢复

## 私人订阅

1. 准备 Linux、Python 3.10 或更新版本与 `systemd`。创建无登录权限的系统用户及同名组 `private-subscription`。将订阅脚本部署到 `/opt/personal-vps-subscription/`，文件由 root 持有。
2. 建立 `/var/lib/personal-vps-subscription/`，其属主为 `private-subscription`，目录权限 700。按 [config.example.json](subscription/config.example.json) 创建配置。准备独立计费配置，参考 [billing.example.json](subscription/billing.example.json)，填写实际套餐额度、到期 Unix 时间戳和校准日期。将经过内核检查的真实 Clash YAML 保存为 `private.yaml`。
3. 用安全随机源生成 32 字节的十六进制订阅令牌，例如在管理员终端用 `openssl rand -hex 32` 直接写入令牌文件。将令牌、YAML 和配置文件权限设为 600，并交给服务用户。保留目录、文件所有权和权限。
4. 在 8443 安装与订阅地址匹配的可信证书，证书和私钥应可由订阅用户读取。采用 ACME HTTP-01 时，按证书签发工具配置 webroot，验证 80 端口挑战。IP 地址证书须使用支持 IP SAN 的签发方式。续期可用 [certificate_hook.py](subscription/certificate_hook.py)，运行前确认配置的 TLS 路径和服务名一致。
5. 安装 [订阅服务单元](systemd/personal-vps-subscription.service)，完成配置后依次执行 `systemctl daemon-reload` 和 `systemctl enable --now personal-vps-subscription.service`。通过 HTTPS 测试正确令牌能下载配置，随机无效令牌返回 404，80 端口仅提供 ACME 挑战。订阅 URL 格式为 `https://<服务器地址>:8443/sub/<令牌>`。

## V.PS 用量与到期日

1. 为 V.PS 查询使用权限尽量窄的账号，准备官方刷新令牌。创建无登录权限的 `personal-vps-api` 系统用户及同名组。将 [vps_usage_sync.py](subscription/vps_usage_sync.py) 部署到 `/opt/personal-vps-subscription/`。
2. 参考 [vps-api.example.json](subscription/vps-api.example.json) 创建 root 持有的 `/etc/personal-vps-api.json`，填写服务 ID 和 VM ID，文件需可由同步用户读取。创建 `/var/lib/personal-vps-api/`，属主及属组为 `personal-vps-api`，权限 700。目录下 `auth.json` 设为 600，由该用户持有，内容格式为 `{"refresh_token":"<刷新令牌>"}`。
3. 创建 `/var/lib/personal-vps-api-usage/`，属主为 `personal-vps-api`、属组为 `private-subscription`、权限 2750。同步用户写入 640 的用量快照，订阅用户可读取快照。安装 [同步服务](systemd/personal-vps-usage-sync.service) 和 [计时器](systemd/personal-vps-usage-sync.timer)。
4. 执行 `systemctl daemon-reload`，单次启动同步服务并检查日志和用量。确认数据与 V.PS 面板同周期后启用计时器 `systemctl enable --now personal-vps-usage-sync.timer`。订阅加载 `provider_usage_file` 后，客户端下次刷新即获取用量和到期日。

此实现从 VM 详情读取收发字节，从服务详情读取续费日期，约每五分钟查询。用量异常或接口临时不可用时保留上次成功读数。首次还没有快照时使用网卡估算。额度来自计费配置。变更套餐后更新额度。换实例时应重新核对 API 收发计数是否与套餐同时重置。

## 日常发布与回滚

- 更新规则时先保留服务端当前 YAML；本地通过 Mihomo 检查后上传到目标目录内的临时文件，确认所有权和权限再原子替换。通过原订阅校验 HTTPS 和内容一致后刷新客户端，检查实际代理链。
- 8443 规则先判断端口，再判断服务器 IP。切换规则时保留 TUN 的服务器 IP 排除。需要测速或变更主备时先留可用的管理连接。
- 订阅异常先查独立订阅服务、8443 监听和证书链；API 查询异常检查同步日志、授权和快照时间。令牌过期或撤销后在服务端重新授权。
- 规则回滚用备份 YAML 原子替换，再刷新客户端。同步回滚先停止计时器，移除订阅配置中的用量快照路径并单独重启订阅服务。代理屡次异常时通过独立 SSH 或供应商控制台恢复已验证的 sing-box 配置及防火墙。
