# 内容维护

按本次对象选用以下方法，不要求固定表格、字段或全历史审计。

## 归属与依据

- 全局指令只放各类任务都需要的通用行为与必要路由；某类工作流即使跨项目使用，其范围、步骤和限制仍归对应技能。项目目标、规则、参数、方法、状态与作品归项目资料；长期记忆只保留已确认的稳定用户事实及未被其他权威正文承接的跨项目偏好，不复制执行规则。用户说“记录一下”时先判断内容归属，不默认写入全局指令或长期记忆；过程证据是否留存取决于实际用途，不因信息归属而必须保存。具体记忆位置及更新权限遵循当前宿主，不将项目细节复制到全局记忆。
- 新要求主动更新所属权威正文，无合适归属时新建规则并补导航，不另等维护提醒。分清规则、可选方法、当前状态和依据，不为分类拆文件。专题有独立用途且影响读取时再拆分，不保留多份正文。
- 先查当前入口及相关条目，仅在缺口、矛盾或追溯需要处检索历史。阅读必要上下文、确认回复与实际结果；聊天标题和旧工作目录不证明当前归属。复杂时可临时对照“决定—对象与条件—依据—当前正文—处理”，不新增长期台账。

## 文件与导航

- 按实际用途而非扩展名归类。长期复用且持续维护的资料统一用.md，已有原件直接复用；长期维护的.md均为项目规则，挂入所属导航，正文独立可用并重点维护。
- 导航只挂接规则及技能规范，不挂接一次性业务文件、状态记录、素材、成果或过程证据。复用参数集中在所属项目的一份独立参数规则，不重复或预建空文件。
- 非规则文件仅随相关任务查用、修改；学习断点、源码、配置等只更新当次必要内容，不因留存而登记清单、维护状态或检查旧路径。用户可自行处置资料，不据旧位置恢复跟踪。

## 临时事项接续

适用于各项目。长期规则只维护接续机制，具体临时任务、一次性安排及本次限定不得写入规则正文或长期记忆。

- 有未完成事项需要跨聊天接续，或用户明确要求“下次继续、先记着”时，在所属项目根目录按需创建“临时接续/”，一事一份以事项命名的.txt；当场完成的不留，未产生事项不预建目录。子目录任务使用所属项目的同一接续目录，不另建副本。接续条属于一次性任务状态，不挂规则导航。
- 只记目标、适用条件、本次限定、已完成内容、下一步、必要材料位置及清除条件；有任务回执时保留必要防重信息，不保存凭据。已有制作状态、学习进度等正式状态记录继续在原处维护，不复制进接续条；只补原状态未承载的一次性安排。
- 进入项目时检查接续目录是否存在并查看事项名称；仅对当前任务相关或用户要求继续的事项读取、核对现状并执行。未到触发条件或与本次无关的事项保留，不擅自启动；已失效、与新要求冲突的内容不作为当前授权。
- 接手时标记所属聊天及更新时间；发现其他聊天正在处理时先核对，不重复执行。更新或清除前重读当前文件，若已被其他聊天修改，先合并或核对；只处理自己接手的对应事项，不覆盖并发更新，不因标记较旧就认定可以接管。
- 事项落实并核实清除条件后自动删除对应接续条，不在刚读取或仅表示接手时删除；中断或受阻则覆盖为最新断点，不追加历史。用户明确取消或新安排已完整替代时清除旧条；目录为空后删除空目录。保留未完成任务实际依赖，成果与其他材料按项目规则处理，不随接续条误删。
- 接续及清除由助手在进入项目、相关任务执行和收尾时完成，不设后台定时任务，不建已办档案、接续日志、备份或维护履历，也不删除聊天历史。此机制统一适用于各项目；项目默认不留临时任务文件的要求，对本节所需的未完成接续信息保留例外。

## 改写与方法提炼

- 保留影响执行的主体、触发条件、时点、范围、例外和完成标准；有判别作用的原话或示例保留在权威正文。“提交前”与“提交后”不能概括为“提交时”，“准备执行”不能缩成“已执行”。
- 按独立条款比较新旧决定，确认对象和条件后直接替换冲突旧正文，保留其余有效条件，历史不得恢复已撤销要求。技能变更核对最新要求与项目适用条件，同步源码和安装副本；定向修正受影响的入口、引用与调用链，使旧要求退出当前指导；不另建变更台账，也不改写宿主历史。新要求已明确时无需再次追问旧决定；只有影响本次处理的含义仍不清时才核对原话。
- 区分方案认可、获准执行、实际执行与验收通过；区分来源陈述、推断、实际测试、用户评价和未验证部分。保留用户质量目标，同时不将目标写成已达到；局部成功不代表整体验收，局部失败不否定已验证能力。
- 方法仅在用户或项目规则要求提取时维护，正文写清问题、做法、适用条件与限制；必要来源可简述或引用公开资料，不强制链接案例、工程、对照图或分析JSON。示例、工具默认值及单次成功的参数或方法不作通用限制；研究建议与真正运行过的方法分别说明。
- 新证据合并或修正已有条目，不反复追加同义总结。相似表述若约束不同对象或条件，不视为重复；历史、原件与恢复资料的去留按用户要求、项目政策、宿主限制及实际用途判断。
- 修正后检查：关键决定与例外是否仍有归属，下一动作是否明确，方法能否按条件选择，证据是否仍支持结论。不以字数减少、关键词存在或链接通过代替含义核对；必要时在隔离材料上演练接续，简单更正不建立额外演练资料。

## 个人技能 GitHub 同步

- 个人技能新增或更新后，在完成必要验证、同步源码与安装副本后，将本次变更同步到 [Codex skills](https://github.com/haochenzq/Codex-skills)。这是用户的持续授权，无需逐次确认；本次用户明确限制上传时遵从当次要求。只同步个人技能及必要配套，不扩展到系统技能或第三方插件。
- 基于仓库当前版本追加提交，保留历史及无关内容；上传前核对本次源码，不包含凭据、Cookie、用户素材、真实任务回执、缓存或第三方依赖目录。
- 上传后核对远端提交与本次文件内容，再报告同步完成。遇到网络、认证或权限阻塞时，完成可进行的本地维护并明确说明未同步项及最小恢复步骤，不把本地更新当作远端已完成。

## 宿主记忆与遗忘

只按当前宿主允许的方式更新记忆。要求追加更新记录时，不直接改生成索引或摘要；区分“记录已提交”“权威正文已修改”和“检索已生效”，只报告实际确认的状态。异步更新未体现时，以当前权威资料纠正本次判断，说明未确认范围，不重复追加或自动建立监测。

用户要求忘记或移除信息时，检查可控制的活跃来源及相关别名，使其退出当前指导；宿主保留的历史不当作活跃违规项，也不承诺删除无法控制的历史。历史路径仅为定位线索，只在实际接续需要时核对，不持续追踪用户移动或删除的旧资料。
