# 文件整理

## 判断范围与用途

目录、名称、编号和留存要求采用各项目规则，不按题材建立通用目录模板。项目总目录保持子项目边界；项目没有明确规定时按实际用途和已授权任务处理，不凭“正式”“测试”“已导出”等标签一刀切，不预建空目录或维护体系。

按用途区分成果、当前依赖、过程材料与未完成任务断点，保留用户原件、所需成果及当前任务实际依赖。验证通过后按项目政策处理过程文件、临时备份与必要状态，再报告完成；不等待反馈，也不为日后可能恢复、重建或修改留存过程资料。明确续作所需依赖、共用资产和未知任务单独核对；文件独有、曾用于验证、仍被引用或理论上可恢复均不足以长期保留，不另建证据档案。

## 盘点与操作

- 清理前，先把用户要求保留且仍混在过程目录内的成果归入项目规定的交付位置，核对实际文件可用及必要引用后再清理过程文件；已在正确位置的成果不重复搬运。工具必须使用的临时位置不因此变成长期保存位置。
- 空间盘点递归读元数据，按任务展示主要占用、大文件、生成产物线索及遗漏范围，不默认读取全部正文。展示深度不限制统计；不跟随链接，目录包含关系不相加，部分统计不称完整总量。
- 缓存、帧序列、临时导出及旧日志只是线索。删除前核对生成者、当前真实依赖、占用、保留成果及实际恢复需求；用户已确认无需重建时不要求保留再生成条件。状态不明保留受影响部分；名字、大小、日期或同哈希不单独作为删除依据。
- 删除使用核实后的具体绝对路径，确认解析后仍在本次授权边界内；不以通配符混删整个项目。Windows直接操作全程使用同一Shell及`-LiteralPath`，不把枚举结果拼接给另一Shell。已有授权覆盖的清理直接执行，不另建审批轮次或重复清单。
- 迁移前核对根边界、链接/硬链接、目标冲突及并发变化；修正受影响的入口、相对路径、脚本父目录定位、安装和恢复引用。源码与安装副本按所属发布方式同步；实际可用性验证后才处理旧位置。
- 修改前文本及操作回执只在本次操作尚未验证完成时暂存；完成后按项目政策清理，不为清理另留长期清单、校验包或整套备份。同盘移动或隔离不算释放空间；日志不能恢复已永久删除的内容。
- 需要确定性文件操作时使用本技能[工具](tool-usage.md)。遇阻先区分当前会话权限、自动审查拒绝/超时、工具保护与文件占用；只暂停受影响部分，继续其余已授权工作。按原因补足证据、申请必要权限或采用实质更安全的方案；明确拒绝后不换Shell、改模式、虚报生命周期或间接执行同一删除。仍无法继续时说明具体路径、原始原因与最小必要用户操作。工具支持范围与项目留存政策分别判断，不因超出工具能力而擅自扩展它。

## 核验与收尾

核对保留成果、当前入口、受影响引用和当前未完成操作的必要断点；根据对象验证程序调用、素材对应或学习断点等实际用途。优先本地或模拟验证，不为整理重跑云生成。任务收尾只检查本次产生的临时材料，不自动清理共享环境或其他项目。

复用已有检查，按任务简要报告实际变化及阻塞；用户关心空间时才统计删除数与逻辑字节，未测量不声称磁盘增量。不强制另存详细清单或机器记录；确需操作回执时仅在执行与核验期间使用，未完成操作保持可接续。
